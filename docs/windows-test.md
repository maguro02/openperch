# Windows 実機テスト

描画・透過・Win32 の挙動は CI では確かめられないため、Windows の実機で次の項目を確認します。開発機は WIN-D を兼ねます。

## 結果の記録

結果は `docs/test-runs/<日付>-<Phase>.md`（例: `2026-11-20-P6.md`）にチェックリストとして記録します。下の各表の「状態」には、最新の記録の結果（未実施・合格・不合格）を書き、記録ファイルへリンクします。

記録ファイルの形式:

```markdown
# <日付> <Phase>

- ビルド: <アプリのバージョン>（コミット <SHA>）、開発ビルドかどうか
- 機材: WIN-D / WIN-I / VM-C（機材の表の記入日）
- 構成: モニタ・拡大率・HDR・GPU など、項目に関係する設定

| ID | 結果 | 計測値 | メモ |
|---|---|---|---|
| W-ENV-01 | 合格 | 10/10、最大 140 ms | |
```

- 購入したアバターや衣装のスクリーンショットは載せません。画像が必要なときは TestDummy で撮ります。
- 診断ログやダンプを貼るときは、パスではなく exportId だけが出ていることを確かめます。

## W-RND（描画）

各項目で次の判定 R1〜R4 を確かめます。

| 判定 | 内容 |
|---|---|
| R1 | 診断の alpha スクリーンショットで、rgb > a + 2/255 の画素が 0.1% 未満 |
| R2 | グレーランプと暗部のグラデーション（sRGB 0.02〜0.1）で、誤差が 1/255 以下 |
| R3 | EnvDriver の単色背景（白 255 と黒 0）をアバターの背後に出し、フレーム固定で同じフレームを両方の背景で画面キャプチャする。a = 1 − (白 − 黒)、色 = 黒 / a で復元した値と、alpha スクリーンショット（非乗算に戻したもの）との差が、a ≥ 0.1 の画素で 2/255 以内（SDR の FHD モニタで行う） |
| R4 | ヒットテストの判定が「alpha > 0.1」と境界 4 px 以内で一致し、遅延は 2 フレーム以内 |

### 計測方法

- **台本の実行**: `OpenPerch.EnvDriver` がテスト用の窓を台本どおりに動かします（移動、リサイズ、最小化、最大化、閉じる、別の窓で覆う、DPI の異なるモニタへの移動、全画面）。各操作の QPC 時刻を記録します。
- **アプリ側の記録**: アプリの診断ログは、フレームの開始時刻、状態遷移、面の再計算、足元の座標を QPC 時刻付きで記録します。
- **判定**: EnvDriver の記録とアプリの診断ログを QPC 時刻で突き合わせ、操作から落下の開始・着地・再表示までの時間とフレームを求めます。
- **位置の誤差**: 診断の「面と足元の可視化」（面の区間・Floor・足元・遮蔽矩形を線で描く）を表示した状態で画面をキャプチャし、線の位置の差を測ります。
