# エクスポーター

`com.openperch.exporter` は、VRChat のアバタープロジェクトに入れて使う Unity Editor 拡張です。自分のアバターとモーションを、OpenPerch のアプリが読み込む `.opk` ファイルに書き出します。

## 状態

| 機能 | 状態 |
|---|---|
| VRChat SDK を使わない書き出し（Generic アダプタ） | 未実装 |
| VRChat SDK を使う書き出し（`OpenPerch.Exporter.VRChat`） | 未実装（ゲート L の後に作る） |
| モーションの書き出し | 未実装 |
| VPM リポジトリでの配布 | 未公開 |

ゲート L は、VRChat SDK のビルド処理を書き出しに使うことについての法務確認です。確認が済むまで、SDK を参照・実行する部分は作りません。

## 前提

| 項目 | 条件 |
|---|---|
| Unity | 2022.3.22f1（VRChat の指定）。2022.3.22f1 以上 2022.3.62f3 以下なら書き出せます。6000.x では「Unity 6 版アプリでのみ読めます」と警告して続行し、それ以外の版では中止します |
| VRChat SDK | SDK3 Avatars 3.7.0 以上 |
| レンダーパイプライン | Built-in |
| Color Space | Linear |
| ビルドターゲット | Windows（x86_64）。Windows の Graphics APIs に Direct3D11 を含むこと |

## 導入

VRChat Creator Companion（VCC）か ALCOM を使います。

1. Settings → Packages → Add Repository で、OpenPerch の VPM リポジトリを追加します（URL は公開時にここへ記載します）。
2. プロジェクトの Manage Project で「OpenPerch Exporter」を追加します。依存する「OpenPerch Runtime」も一緒に入ります。

## 使い方

メニューの Tools → OpenPerch → Exporter でウィンドウを開きます。表示は日本語と英語を切り替えられます（既定は OS の言語）。

### 初回の同意

初めて書き出すときに、次の注意事項への同意を求めます。同意はこの PC の Unity に保存します。

- 個人利用に限ること
- アバターやモーションの規約（VN3 ライセンスなど）を確認すること
- 書き出した `.opk` を他人と共有しないこと
- 書き出しでは、VRChat SDK のビルド処理を VRChat 以外の用途で実行すること

### 事前チェック

「事前チェック」は、元のアバターを変更せずに前提を確かめます。違反している行には「修正する」ボタンが付きます。

| 検査 | 「修正する」でできること |
|---|---|
| Windows の Graphics APIs に Direct3D11 が無い | Direct3D11 を追加する |
| ビルドターゲットが Windows でない | Windows に切り替える |
| 前回の一時フォルダが残っている | 削除する |
| Color Space が Linear でない | 説明だけ（自動では変えない） |
| ロックしていない Poiyomi（ThryEditor）のマテリアルがある | ― （アバタータブで同意すると書き出し時にロックする） |
| `VRChat/` 系のシェーダーを使っている | ― （アバタータブの差し替えオプションを使う） |
| PC で使えないテクスチャ形式（ASTC・ETC・PVRTC など）がある | ― |
| 許可リストに無いコンポーネントがある | ― （書き出し時に除去する） |

### アバターの書き出し

アバタータブで次を指定して書き出します。

- 対象: シーン上のアクティブなアバターのルート
- 出力先: 既定は `<プロジェクト>/OpenPerchExports/`（Assets の外）
- 新規か、前回の書き出しの更新か: 更新を選ぶと前回と同じ lineageId で書き出し、アプリ側で置き換えとして取り込めます
- Poiyomi のロックへの同意: ロックしていないマテリアルがあるときだけ表示します
- `VRChat/` 系のシェーダーを、複製したマテリアル上で lilToon（無ければ Standard）に差し替えるオプション

初回の書き出しでは、シェーダーのコンパイルに数分かかることがあります。

### モーションの書き出し

モーションタブでは、FBX をクリップ単位の行に展開し、行ごとに役割・ループ・重み・`walkSpeed`・`seatHeight` を設定します。`seatHeight` は自動で推定した値を上書きできます。Humanoid として設定済みの FBX か、Humanoid の .anim を使ってください。

### 書き出し中とレポート

進捗バーにステップの番号と名前を出します。S04 より前はキャンセルできますが、S04〜S16 はキャンセルできません。

終了後のレポートには、ステップごとの所要時間、失敗したステップ、メッセージコード、プロジェクトへの変更の一覧、「診断情報をコピー」と「エクスプローラーで表示」のボタンが出ます。

| # | ステップ | キャンセル |
|---|---|---|
| S00 | 事前走査 | できる |
| S01 | 環境の確認 | できる |
| S02 | 事前の記録 | できる |
| S03 | クローンの作成 | できる |
| S04 | 前処理（VRChat SDK のビルド前処理） | できない |
| S05 | シェーダーの確定 | できない |
| S06 | 記述子の抽出 | できない |
| S07 | コンポーネントの変換 | できない |
| S08 | コントローラーの変換 | できない |
| S09 | クリップの変換 | できない |
| S10 | 不要なコンポーネントの除去 | できない |
| S11 | 一時アセットの保存 | できない |
| S12 | 合成モードの判定 | できない |
| S13 | シェーダーバリアントの収集 | できない |
| S14 | 監査 | できない |
| S15 | バンドルのビルド | できない |
| S16 | 梱包 | できない |
| S17 | 後始末 | ― （必ず実行する） |

ビルドターゲットが Windows でない場合、S01 で切り替えたうえで書き出しを中止します。切り替えが終わったら、もう一度実行してください。

## プロジェクトへの変更

- エクスポーターは元のアバターではなくクローンを書き出し、プロジェクト全体の保存（`AssetDatabase.SaveAssets`）を呼びません。エクスポーター自身はユーザーのアセットを変更しません。
- S04 の前処理では、VRChat SDK のビルド前処理に登録されたツール（NDMF、VRCFury など）が動きます。これらはプロジェクトのアセットを変更することがあります（Poiyomi のロック、lilToonMulti のキーワード、VRCFury の Write Defaults の修正など。ディスクに書く場合も、メモリ上だけの場合もあります）。
- 変更はレポートに種類別に出ます。一覧が空でなければ、バックアップやバージョン管理で確認してください。

| 種類 | 意味 |
|---|---|
| ModifiedOnDisk | 書き出しの前後で内容が変わったファイル |
| UnsavedChange | メモリ上で変更され、まだ保存されていないアセット。Editor の終了時やプロジェクトの保存時にディスクへ書き込まれる |
| Created / Deleted / Moved | 書き出し中に作成・削除・移動されたアセット（作って消したものは除く） |
| ToolTemp | 上のうち、ツールの一時フォルダ（`Packages/nadena.dev.ndmf/__Generated/`、`Packages/com.vrcfury.temp/`）の配下のもの |

- シーンが書き出し前に保存済みだったのに dirty になった場合は、その旨を表示します。クローンを一時的に置いたことによるもので、内容の差分はありません。
- 一時ファイルは `Assets/__OpenPerchExport/<exportId>/` と `Temp/OpenPerchExport/<exportId>/` に作り、終了時に削除します。Editor が書き出し中に落ちた場合は、次の起動時に確認ダイアログを出してから、これらを削除します。
- エクスポーターは VRChat への通常のアップロードには介入しません（`IVRCSDKPreprocessAvatarCallback` を実装しません）。

### クローンの名前

S03 で作るクローンには、元のアバターと同じ名前を付けます。名前に "(Clone)" が付いていると、VRCFury が元のアバター側に保存処理を行うためです。

| 項目 | 状態 |
|---|---|
| 同じ名前のクローンで、元のアバターとプロジェクトのアセットが変わらないこと（T-EXP-ORIG） | 未確認 |

## コンパイルの確認

`OpenPerch.Exporter.VRChat` は、VRChat SDK（`com.vrchat.avatars`）があるときだけコンパイルされます。SDK の版によって有効になる分岐があるため、SDK の最低版と最新版の両方でコンパイルを確かめます。

| 定義 | 有効になる条件 |
|---|---|
| `VRCHAT_AVATARS_PRESENT` | `com.vrchat.avatars` がある（アセンブリ全体のコンパイル条件） |
| `OP_VRC_GLOBAL_COLLIDER` | `com.vrchat.avatars` 3.10.4 以上 |
| `OP_VRC_CONTACT_BOX` | `com.vrchat.avatars` 3.10.4 以上 |

### SDK の最低版と最新版

VRChat SDK を実行する作業なので、ゲート L の後に行います。

1. VCC で、Unity 2022.3.22f1 の Avatars プロジェクトを 2 つ作ります。
2. Manage Project で、1 つ目は `com.vrchat.avatars` を 3.7.0（[前提](#前提)の表に書いた下限。最低版）に、2 つ目は 3.10 系の最新のパッチ（最新版）にします。最低版を下限そのものにするのは、下限より後の版で入った API を使ってしまったときに検出するためです。
3. 各プロジェクトの `Packages/` に、リポジトリの `packages/com.openperch.runtime` と `packages/com.openperch.exporter` をコピーします（埋め込みパッケージになります）。
4. Unity で開き、Console にコンパイルエラーが無いことを確かめます。
5. `Library/ScriptAssemblies/OpenPerch.Exporter.VRChat.dll` が作られていることを確かめます。最低版では `OP_VRC_*` が無効の側、最新版では有効の側がコンパイルされます。
6. 結果を下の表に記録します。

### Unity 6

エクスポーターは、VRChat の SDK が Unity 6 へ移る場合に備えて、Unity 6000.x でもコンパイルが通る状態を保ちます。確認は、Mac で `tools/run-unity-tests.sh` を実行したときの `harness-6000.3-compile` で行います。

- スクリプトは、ExporterHarness（SDK なし）と `packages/` を、リポジトリの中と同じ相対位置のまま一時フォルダにコピーし、そのコピーを Unity 6000.3 のバッチモードで開いて、コンパイルエラーが無いことを確かめます。新しい版の Unity は開いたプロジェクトを移行するので、元のハーネスは開きません（ハーネスの Unity の版は 2022.3.22f1 のままです）。
- 使う Unity は、環境変数 `UNITY_6000_3` で指定したもの、無ければ Unity Hub の既定の場所にある 6000.3.x です。どちらも無ければ、この項目は SKIP になります。
- 手で確かめるときも、ハーネスと `packages/` を同じ相対位置でコピーします。ハーネスの `Packages/manifest.json` は runtime と exporter を `file:../../../packages/...`（`Packages/` からの相対パス）で参照するので、ハーネスだけを深さの違う場所にコピーすると、パッケージを解決できず確認になりません。

## 書き出したファイル

- `.opk` は暗号化していないので、中身を取り出せます。他人と共有しないでください。
- CRC-32 と SHA-256 で検出できるのは破損だけで、改ざんは防げません。
- アプリには、自分で書き出したファイルだけを読み込ませてください。
